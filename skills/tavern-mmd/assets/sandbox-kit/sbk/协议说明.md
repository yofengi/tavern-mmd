# SBK 状态协议与状态栏说明

适用：MMD 沙盒模式（`c<卡片ID>.sbx.aitchat.org`）。依据 `资料/基座事实卡.md`，全部结论来自沙盒源码逆向 + 真机探针实测。

本文件两部分：**上半给做卡人**（配 schema、选 `modes`、避坑），**下半给模型**（可直接粘进 `personality` 的输出约定）。

## 一、协议形态

模型在正文末尾输出一个状态块：

```
[状态]
血量: 72/100
金币: 380
好感: 熙宁=61, 阿澈=25
标记: 中毒, 疲劳
[/状态]
```

正式模板必须首尾一致。解析器虽然容忍部分括号漂移，但 persona、开场白和交付示例一律写标准 `[状态]…[/状态]`，不要把容错能力当推荐格式。

### 1.1 块标记

默认块名 `状态`，三种括号族**都认、可混用**：`<状态>…</状态>`、`[状态]…[/状态]`、`【状态】…【/状态】`。

> **一律用方括号 `[状态]`**（plan.md 已裁决第 9 条）。
> 事实卡 §5.4：worker 用 `/<\/?([\u4e00-\u9fa5a-zA-Z0-9_]+)(\s+[^>]*)?>/g` 剥掉非白名单标签，
> `<状态>` 是中文标签名，**会被整个删掉**（文字保留、标签消失）。
>
> 关键在于**剥壳发生在正则管线【之后】**，于是尖括号在链路上是「半死」的：
> `status` 那条外壳规则的匹配式**看得见** `<状态>` 所以能匹配成功；但只要有任何一段
> 从**气泡文本**读取标记的路径（`hydrate()` 拿到的节点 `textContent`、你自己写的
> `feed(payload.content)`、精简条的 `feed`），标记那时已经被剥掉了，解析就认不出块。
> 表现是「气泡里那一块渲染出来了，别的地方死活不动」——极难排查。
> 方括号不是标签，**全链路都活着**。
>
> **别把这条改回尖括号。** 基座对两种都做了兜底（`hydrate()` 拿到裸块体时会用
> `SBK.parse.wrap()` 补回方括号再解析一次），所以改成尖括号短期看着也能跑——
> 直到某天兜底路径没命中，状态栏就变成一坨可见的原始文字。

改块名：`SBK.parse.config({ block: 'STATUS' })`。

### 1.2 字段行

一行一个 `键: 值`。**冒号全角半角都认**（`:` `：`），只在**第一个**冒号处切分，所以 `时间: 12:30` 不会丢掉 `30`。

值按下表判定，**表的顺序就是优先级**（对应 `protocol.js` 的 `value()`，自上而下逐档尝试）。每档都要求**结构完整**才认，否则一路降级到文本：

| # | 形态 | 类型 | 示例 | 结果 |
|---|---|---|---|---|
| 1 | 纯数字 | `num` | `银钱: 380` | 数值 380 |
| 2 | `数%` | `bar` | `进度: 72%` | 进度条 72/100 |
| 3 | `a/b`（**恰好两段且两段皆纯数字**）| `bar` | `体力: 84/100` | 进度条 84/100 |
| 4 | `名\|当前/上限`（右段必须是 `a/b` 纯数字）| `level` | `境界: 炼气三层\|120/300` | 等级名 + XP 条 |
| 5 | `键:值` 用 `\|` 分项 | `kvlist` | `装备: 头:斗笠\|身:麻衣` | 竖排键值 |
| 6 | `键:值` 用逗号或空白分项 | `stats` | `属性: 攻:12 防:8 敏:15` | 属性 chip 网格 |
| 7 | `名=数` 分隔（**右侧必须是数字**）| `entities` | `好感: 苏九=61, 阿澈=25` | 多实体表 |
| 8 | 逗号分隔的纯文本（**≥2 项**）| `tags` | `标记: 中毒, 疲劳` | 标签组 |
| 9 | `-` 分段（≥2 段、**不能全是数字**）| `path` | `位置: 内城-东市-药铺` | 面包屑 |
| 10 | 其余 | `text` | `暗号: 北门/东街/西市` | 一行文本 |

逗号**全角半角都认**，顿号 `、` 也当分隔符（`,` `，` `、`）。竖线 `｜`、等号、斜杠、百分号、减号的全角形态（`｜＝／％－`）同样归一化，全角数字 `７２` 折成 `72`。**竖线是主分割符**（`level` 与 `kvlist` 都靠它），中文输入法下吐出全角竖线是常态，所以它必须被归一化。

### 这个顺序为什么是这样（每一处都在防一类误判）

- **结构类型排在 `bar` 之后** → `84/100` 仍然是进度条，`72%` 与纯数字更早就返回了。既有类型零影响。
- **`stats` 排在 `tags`/`entities` 之前** → `攻:12, 防:8` 若先过 `tags`，会被逗号切成两个纯文本 chip，`键:值` 结构永久丢失。而 `entities` 认的是 `名=数`（等号），与 `键:值`（冒号）不冲突，提前 `stats` 不会抢走 `苏九=61, 阿澈=25`。
- **`level` 排在 `kvlist` 之前** → 两者都用 `|`，靠「右段是否 `a/b` 纯数字」区分。`level` 判定更严（必须是数字），**先严后宽**才不会互抢：`3/3|暂无` 右段不是数字 → 不是 `level`。
- **`path` 排在 `tags` 之后、`text` 之前** → `内城-东市-药铺` 没有逗号所以走不到 `tags`；把它压到最后，能保证任何带逗号的值（已被 `tags`/`entities` 吃掉）都不会被误判成路径。
- 🚨 **为什么 `2026-08-26` 不会被误判成 `path`**：`toPath()` 有两道闸——① 段内出现 `|` `:` `=` 直接判负（那是别的类型的地盘）；② **全部段都是纯数字就判负**。日期 `2026-08-26`、编号 `1-2-3` 都是全数字段 → 落回 `text`。而 `内城-东市-药铺` 至少有一段非数字 → 认成路径。另外空段也判负：`a--b`、首尾带横线的 `-东市-` 都不是路径。

判定为什么这么严：`暗号: 北门/东街/西市` 是三段不是两段，不是进度条；`任务: 找到钥匙=打开门` 右侧不是数字，不是实体表。**这些都会正确落成文本**，而不是渲染出一个诡异的控件。宁可显示成一行字，也不能因为模型写歪一个字段就渲染出畸形控件。

### 第三段 = 成因说明，自动折进 tooltip

`stats` 与 `kvlist` 的每一项都支持**第三段**：`键:值:说明`。只切**第一个**冒号，所以说明里还能带冒号。

```
属性: 攻:12 防:8:破甲 敏:15
装备: 头:斗笠|身:麻衣:防御+2|腰:药囊
```

带第三段的项会渲染成「触发词 + 折叠的说明」，**点击 toggle** 展开。🚨 不用 CSS `:hover`——沙盒是移动端 webview，**hover 在触屏上不成立**。

### 1.3 容错清单（都已自测覆盖）

以下漂移**全部不影响解析**，坏行只跳过自己，绝不让整块失败：

- 多余空格与制表符：`   血量  :   72 / 100   `
- 中英标点混用：`血量：72／100`、`好感：熙宁＝61，阿澈=25`
- 全角数字：`体力：８０/１００`
- 标记内空格：`< 状态 >` / `</ 状态 >`
- 字段顺序任意变化、只输出部分字段（缺项不渲染空行，不报错）
- markdown 漂移：`- 血量: 72/100`、`**金币**: 9`（列表前缀与星号会被剥掉）
- 无冒号的废话行 → 跳过并计数（`skipped`），不进状态
- 重复键 → **后者覆盖前者**，字段位置保持首次出现的顺序
- 缺闭合标记 → 从开标记吃到正文结尾（记一条告警）
- 一条消息里多个状态块 → 合并，全部移除
- 负数与小数：`温度: -12`、`倍率: 1.5`
- 超长值 → 单值截到 200 字符，列表条目截到 24 条（见下条「为什么」）

> 截断不是洁癖。事实卡 §5.2：单条正则规则的输出预算是 `max(262144, 输入长度×4)`，
> **超限整条规则回滚**，页面上该规则完全不生效，只留一条告警。从解析源头掐掉最省事。

## 二、三个 `modes` 各干什么

事实卡 §5.6 是这里全部设计的前提：**功能栏是静态的**。`h_()` 只在装载时跑一次，它的正则输入是卡片 `statusbar` 字段**自身**而不是消息内容，主包里**没有任何重渲染路径**。

→ 「功能栏上的东西跟着对话变」这件事**只能靠 JS 改 DOM**，指望正则刷新一定失败。这是做卡人踩得最多的坑。

2.0 的 `modes` 是**三件职责不同的东西**，不是「同一份 schema 的几个渲染器」：

| | `status` | `chrome` | `pinned` |
|---|---|---|---|
| 是什么 | **唯一的状态数据渲染器** | 功能栏入口按钮组 | 功能栏**精简条** |
| 位置 | 每条 AI 气泡内 | `[data-slot="statusbar"]` | 功能栏，chrome 的兄弟节点 |
| 渲染业务数据 | ✅ 全套（分组/进度条/chip） | ❌ **完全不渲染** | 单行、1–3 项、纯短文本 |
| 更新 | 每条消息 mount/done 时就地升级 | 静态，装一次 | JS 订阅 `state`/`done` 重绘 |
| 随滚动 | 跟着气泡走 = **天然历史留痕** | 不动 | 不动 |
| 默认 | **true** | **true** | **false** |

**这个分工是 2.0 的地基。** 1.0 的 `{hud, snapshot}` 是两个渲染器渲染同一份 schema，示例配置两个都开 → 实机截图里同时出现**两个一模一样的状态面板**（字段、取值、样式全同）；而且 `hud` 把状态数据放进了功能栏，**违反 MMD 惯例**——功能栏历来放全局美化/侧边栏这类 chrome，状态栏历来在气泡内。性质是角色分工错，不是代码 bug。

三者两两不重复：`status` 在气泡内、`chrome` 不含数据、`pinned` 形态被强制区分（单行、无分组、无标签行、不画进度条、自己的 `.sbk-pin*` 命名空间）。

### 2.1 `status`：气泡内状态面板（默认开，绝大多数卡只需要它）

一条正则规则把状态块换成待升级的壳，再由 JS 就地渲染。**计算全在 JS，正则只搬字符串。**

```js
SBK.ui.snapshot.auto({ fields: ['体力', '银钱', '好感', '标记'] });
```

装一次即可，它自己订阅 `mount` 与 `done`（**两者都有补发**，所以历史气泡也会被升级）。正常情况下用 `SBK.boot()` 就够了，不必手写。

- **只吃 AI 气泡里的内容。** 这条路径天然安全：§5.6 **用户消息不跑正则**，所以用户在输入框打一句 `[状态]体力: 999/100[/状态]` 不会变成外壳，也就不会被 `hydrate` 升级。
- 幂等：升级完的节点会被打上 `.sbk-snap--done`，`mount` 补发时不会重复渲染。
- 解析不出字段就**原样留着**（补一个 `.sbk-pre` 保住换行），比清空成空白块友好。

### 2.2 `chrome`：设置入口（默认开，不渲染业务数据）

```js
SBK.ui.chrome({ hostId: 'sbk-hud', icon: 'wrench', side: 'right' });
// -> { el(), toggle(), panel(), dock() }
```

设置入口。**它不显示任何状态数据**——这正是它与 1.0 的 `hud` 的区别。模块级单例，重复调用返回已有句柄并告警。

**默认形态是 `dock`**：贴视口边缘的一枚**图标**页签，点开是半页抽屉；抽屉里的表单归主题层（`SBK.theme.prefs.pane()`）。旧的功能栏内按钮排（大按钮＋「设置」文字）改为 `form:'bar'` 才用，或在 `ui-dock.js` 被裁掉时自动回落。

换默认的原因是形态冲突：bar 走功能栏行内流，与平台自己的 chrome 挤在一条上，且功能栏实测 `flex-shrink:1` 会被消息区抢高度压扁，观感是「设置按钮镶嵌在页面里」。

三条数量纪律（`ui-dock.js` / `ui-nav.js` 里各有强制实现）：**设置页签全局唯一**（`role:'settings'`，重复加被拒）；**单 pane 不渲染导航栏**；**单 entry 不铺扇形**（自动降级成直达）。作者的扩展页签（图鉴/地图）可以多枚。选型规则见 `references/beautify/sandbox-kit.md` 第 7.5 节。

### 2.3 `pinned`：功能栏精简条（默认关）

真要「体力永远可见」时才开：

```js
SBK.pinned(['体力', '灵力']);        // 或配置里 modes.pinned + pinnedFields
```

- **必须配 `pinnedFields`**，取 `schema.fields` 里的 key，**限 1–3 项**（超出截断；生成器直接报错）。开了却不配，整个模式会被跳过并告警。
- 上限 3 项是**形态约束**不是性能考虑：项数一多就又变成「同一份数据渲染两遍」。
- 值一律压成**短文本**（`bar` 取 `当前/上限`，**绝不画条**），单项超 24 字符截断，保住单行形态。
- 宿主是 `<hostId>-pin`，与 chrome 的 `<hostId>-chr` 是兄弟节点：精简条每次重绘都清空自己的宿主，共用会把入口按钮全擦掉。

### 2.4 `status` 的外壳规则怎么写

`status` 需要**两样东西同时存在**才生效：上面那句 `snapshot.auto()`（订阅 mount/done），加一条把状态块换成待升级外壳的正则规则。**少任何一样都是静默失效**——生成器为此做了**双向**一致性校验（`check_dual_mode`），两样都缺反而无害（模式干脆没开）。

| 字段 | 值 |
|---|---|
| `scriptName` | `sbk-snap` |
| `findRegex` | `/[<\[【]\s*状态\s*[>\]】]([\s\S]*?)[<\[【]\s*[\/／]\s*状态\s*[>\]】]/g` |
| `replaceString` | `<div class="sbk-snap sbk-card sbk-pre sbk-snap--raw">$1</div>` |

🚨 **两个类名都不能少**：`.sbk-snap` 是 `base.css` 重置气泡 `opacity:.9` 与 `white-space:pre-line` 的钩子（缺它排版必烂）；`.sbk-snap--raw` 是 `hydrate()` 找待升级节点的选择器（`SBK.dom.all(root, '.sbk-snap--raw')`，缺它 JS 升级永远不触发，气泡里只会留一段纯文本）。

🚨 **壳内只放 `$1`**，不要再套 `<span class="sbk-label">状态</span>` 之类的装饰：`hydrate` 读的是节点 `textContent`，多出来的文字会被当成块体首行（`状态体力: 84/100` 会被解析成键名 `状态体力`）。

匹配式可以直接从代码里取，不用手抄：`SBK.parse.pattern()` 返回的就是上表那一串。它同时认三种括号族；只想认方括号（推荐形态）的话，这条更短、等效：

```
/\[状态\]([\s\S]*?)\[\/状态\]/g
```

⚠️ **方括号在正则里是字符类的定界符，必须转义成 `\[` `\]`**，闭合斜杠也要写 `\/`。漏转义会变成字符类，匹配行为完全不同。

关于这条匹配式的三个要点：

1. **统一写 `/…/` slash 形态**（约定，非硬性）。`【实机 2026-08-30】`（卡 64304 A/B）复验裸字面量也生效，与 worker 源码 `p()` 的字面量分支一致（宿主包只把 pattern 原样转发、不做分类）。统一 slash 是为跨平台一致（与 `/mmd` 铁律一致）、也符合官方校验文案；生成器对裸字面量出 WARN 不出 ERROR。
2. **块内换行用 `[\s\S]*?`，不能用 `.*?`**。`.` 不跨行，状态块只会吃到第一行。
3. **绝不匹配空串**。§5.2：`empty-match` 判定会让**整条规则被撤销**。本式最少要吃掉 6 个字符（标记本身），安全。

也可以不走 JS 升级、让正则直接吐 HTML，但那样正则得自己算进度条百分比——做不到。所以基座只提供「壳 + JS 升级」这一条路。

### 2.5 `SBK.ui.snapshot(state, schema)` → HTML 字符串

想自己拼 HTML 时用它。返回**字符串**（要塞进 `replaceString`），所以这条路径**不能**用 `SBK.dom.h`。

```js
var r = SBK.parse(text);
var html = SBK.ui.snapshot(r.state, schema);   // 也可以直接把 r 传进去
```

产物长这样（已按净化规则约束）：

```html
<div class="sbk-snap sbk-card sbk-col"><div class="sbk-row"><span class="sbk-label">血量</span><div class="sbk-bar sbk-grow"><div class="sbk-bar__fill" style="width:72.0%"></div></div><span class="sbk-val">72/100</span></div>…</div>
```

**根元素必须带 `.sbk-snap`**（已裁决第 4 条）。`base.css` 靠这个类把气泡的 `opacity:.9` 与 `white-space:pre-line` 重置掉（§7.3 / 硬约束 11）。少了它，排版会烂：`pre-line` 把 HTML 里的换行缩进当真实换行渲染，`opacity:.9` 让整块发灰还建立层叠上下文。基座自己产出的根节点一定带，**手写时别漏**。

产物同时满足（§5.5 净化规则）：无自写 `data-*`（全删）、无 `aria` 属性与 `role`（`ALLOW_ARIA_ATTR:!1`）、属性值不含 `]>` 或 `-->`（`SAFE_FOR_XML` 会删**整条属性**）、只用 `div`/`span`（§5.4 白名单 ∩ DOMPurify）、无换行无缩进（省预算）、零硬编码色值。

## 三、schema

```js
{
  title:  '状态',            // 可选，渲染成一行小标题
  hostId: 'sbk-hud',         // 可选，功能栏宿主容器 id（字符集有规范，见下）
  extra:  false,             // 可选，声明了 fields 时是否把其余字段也渲染出来
  fields: [
    { type: 'section', label: '状态' },          // 版面项：开一张分组卡（无 key）
    '体力',                                     // 字符串 = 用协议推断的类型
    { key: '银钱', label: '钱袋' },              // 改显示名
    { key: '好感', type: 'entities' },           // 强制控件类型
    { key: '经验', type: 'bar', max: 1000 },     // 补上限（模型只给了当前值时）
    { key: '重量', type: 'num', unit: 'kg' }     // 加单位
  ]
}
```

> 🚨 **`persist: true` 已删除。** 它曾被写成「走 `SBK.store` 存档」，但运行时**从来没有实现过**——
> 没有任何一处读它，既不 load 也不 save。现在 `SBK.boot()` 遇到这个键会**删掉并告警**。
> 要存档请显式调用，见 [§4.2 存档](#42-存档sbkstore)。

**宿主 ID 分两层约束：**

- 最终 DOM id（直接传给 `SBK.dom.mountHost()` / `SBK.pinned()`）匹配 `/^[A-Za-z][A-Za-z0-9_-]{0,63}$/`，总长 ≤64。
- 配置里的 `hostId` 和 `SBK.ui.chrome({hostId})` 是会派生后缀的**基名**，匹配 `/^[A-Za-z][A-Za-z0-9_-]{0,59}$/`，总长 ≤60。

基座会追加 `<hostId>-chr` 与 `<hostId>-pin`，所以 60 字符基名派生后恰好仍在 64 字符上限内。非法值会告警并回落默认，不会静默，也不会让两个派生宿主因共同回落而碰撞。

- **权威键名是 `fields`。** `rows` 是容错别名：走 `SBK.boot()` 会被归一化并告警，但**直接调渲染器时不会**——读不到 `fields` 就静默退化成「按模型输出顺序全渲染」，现象是 schema 像根本没生效，极难排查。
- `fields` 缺省 → **按模型输出顺序**全渲染（顺序由 `SBK.parse` 的 `order` 给出）。
- 声明了 `fields` → 只渲染声明过的，顺序按声明。想追加其余字段就加 `extra: true`。
- 声明了但模型本轮没输出的字段 → **跳过**，不渲染空行。
- `_` 开头的键不渲染，留给内部字段（主题偏好就存在 `_sbkTheme` 里）。

### 3.1 版面层：`section` 分组

`section` 是**版面声明，不是数据字段**——它没有 `key`，state 里也没有对应值，`TYPES` 表里也查不到它，由 `tree()` 的分组游标单独处理。

```js
fields: [
  { type: 'section', label: '状态' },
  { key: '体力', type: 'bar' }, { key: '灵力', type: 'bar' },
  { type: 'section', label: '行囊' },
  { key: '银钱', type: 'num' }, { key: '装备', type: 'kvlist' }
]
```

- 遇到 `section` 就**收口上一组、开一张新分组卡**，后续字段累进当前组，直到下一个 `section`。
- 首个 `section` 之前的字段直接进面板，不进任何分组。
- **组内一个字段都没有就不产出这张卡**：连续两个 `section`、或整组字段本轮模型全没输出，都不会留下空卡片。
- 渲染结构：`.sbk-card.sbk-sect` 分组卡，组标题是 `.sbk-label.sbk-sect__t`（主题色小字 + 同色下边框）。三层明度递进（面板 → 分组卡 → 内容区），各带细边框。

**这是 1.0 最大的缺口**：1.0 只有一个容器，20 个字段拉平成一张长表，读者拿不到「哪几项是一组」。

### 3.2 数据类型（十二种，以 `hud.js` 的共享 `TYPES` 表为准；快照出口在 `hud-render.js`）

合法 `type` 恰**十三种＝十二个数据类型 + 一个版面项 `section`**。

写了表外的名字**会告警并按 `text` 渲染**（告警走 `sdk.debug.log`，实机加 `?sdkDebug=1` 可见）。
同一个坏名字**只告警一次**——`state` 每轮都会重跑，逐轮刷屏反而会把真正的错误淹掉。
（旧版本是**静默**回落 `text`，把 `entities` 拼成 `entites` 时页面上只是少个控件、毫无线索；现在有线索了。）

| type | 协议形态（模型怎么写） | 渲染结构 |
|---|---|---|
| `bar` | `84/100` 或 `72%` | 标签 + 进度条槽 `.sbk-bar` > `.sbk-bar__fill`（宽度按百分比）+ `.sbk-val` 显示 `当前/上限`（`unit:'%'` 时显示 `72%`） |
| `num` | `380` | 标签 + `.sbk-val` 数值，可带 `unit` |
| `text` | 任意一行文字 | 标签 + `.sbk-val` 一行文本 |
| `tags` | `中毒, 疲劳` | 标签 + 一排 `.sbk-chip`，行可换行（`.sbk-row--wrap`） |
| `entities` | `苏九=61, 阿澈=25` | 每个实体一行：名字 + 进度条 + 数值。**上限缺省取组内最大值**（也可用 `max` 指定） |
| `path` | `内城-东市-药铺` | 面包屑：`.sbk-chip.sbk-crumb` 段 + 段间 `.sbk-arrow` 的 `›` |
| `level` | `炼气三层\|120/300` | 上行「左等级名 + 右 `120/300`」，下行 XP 条（`.sbk-bar--xp` 金色）。**只有经验段解析成功才画条**，否则只留一行名字，不画 0% 空槽 |
| `stats` | `攻:12 防:8:破甲 敏:15` | `键:值` chip 紧凑网格（`.sbk-chip.sbk-stat`，chip 左 3px 主题色竖条）。第三段进 tooltip |
| `kvlist` | `头:斗笠\|身:麻衣:防御+2` | 竖排「槽位：名」（`.sbk-row.sbk-kv`），信息密度最高。第三段进 tooltip |
| `time` | `第三日 黄昏` / `2026-08-26 19:30` | 紧凑单行（`.sbk-time`）：首段弱化成次要色小字，其余段正文色加重。等宽数字防抖 |
| `summary` | 任意一段叙述文字 | 独立摘要块（`.sbk-sum`）：可折行、保留模型写的换行、左侧强调条 + 第三层底色 |
| `turn` | `3` / `第三幕` / `3/12` | 紧凑角标（`.sbk-turn`）：描边胶囊、贴行尾、主题色。轮次是元信息，形态刻意不像属性行 |

带第三段的 `stats`/`kvlist` 项会包成 `.sbk-tt`（触发词 `.sbk-tt__hit` + 折叠的 `.sbk-tt__box`），**点击 toggle**。它在两条渲染出口都能点：DOM 路径挂函数 handler，字符串路径挂内联 `onclick`。

#### `time` / `summary` / `turn`：只在显式写了 `type` 时才用

这三种是**纯展示**控件（零本地状态、两条出口共用同一份 vnode、格式容错），但**协议不会自动推断出它们**：

```js
fields: [
  { key: '时间', type: 'time' },
  { key: '本轮', type: 'turn' },
  { key: '概要', type: 'summary' }
]
```

**为什么不自动推断**：判断「这行是时间」只能靠猜关键词或猜日期格式，而猜测**不可复现**——
`2026-08-26` 与 `1-2-3` 形状一样（后者是编号），「第三日」与「第三层」差一个字却是两种语义。
一旦猜错就是**静默错显**，比不推断难查得多（`tone` 推断已经踩过这个坑，那里至少还有告警）。
所以模型输出的原始文本仍按既有顺序分类（多半落 `text`），**你写了 `type` 才按这三种渲染**，
基座随后用同一批适配器把值调整成目标形态。

三种都**不解析语义**：`time` 只按空白把值切成「首段 + 其余」给一点视觉层次，不判断哪段是日期哪段是时刻；
`turn` 原样显示 `3` / `第三幕` / `3/12`；`summary` 原样保留换行。**模型写什么就显示什么。**
值为空时这三种**不产出空壳**（整行跳过），不会留下一个空角标或空块。

强制 `type` 覆写时基座会**重新适配值**，且走的是**与自动推断同一批解析器**（`SBK.parse.struct`）——不会出现「自动认出的 `stats`」和「schema 写 `type:'stats'` 的 `stats`」两套行为。所以把 `text` 强制成 `tags` 不会按**字符**切成一堆 chip，强制成 `bar` 不会渲染出 `NaN` 或 `380/undefined`（没给 `max` 时按百分比常规取 100）。强制时还会放宽最少项数到 1 项，并允许 `level` 只有名字没有经验条——你明确写了 `type`，基座就尽力渲染成那个控件而不是退回文本。适配失败会告警并渲染一个空壳，不抛异常。

### 语义色：`bar` 按字段自动分色

`bar` 字段没写 `tone` 时**按 key 推断**，四种：
`hp`（血量/生命/气血/体力…红）、`mp`（灵力/法力/魔力/内力/真气…蓝）、
`sp`（精力/耐力/饱食…绿）、`xp`（经验/修为/熟练…金）。
`level` 的经验条恒为 `xp`。`num`/`text`/`tags`/`entities` **不染色**
（实体是人名，没有 hp/mp 语义，保持强调色）。

显式声明可覆盖推断，两级都支持：

```js
{ key: '体力', type: 'bar', tone: 'sp' }          // 字段级：只染这一条
{ type: 'section', label: '状态', tone: 'hp' }    // 组级：组内 bar 与 stat 左竖条统一染色
```

**字段级恒优先于组级**：组级靠 `--sbk-tone` 继承下传，字段级是元素自身声明，层叠上必胜。
`tone` 写了 `hp|mp|sp|xp` 之外的值会**告警并忽略**，不会静默上错色
（告警走 `sdk.debug.log`，实机要加 `?sdkDebug=1` 才看得到）。

> ⚠️ **「体力」默认判 `hp`（红）**，这是取舍不是普适真理。它在中文卡里是真实歧义：
> 仙侠卡里通常就是血条（且往往没有单独的「血量」字段），战斗卡里可能与「血量」并存作耐力用。
> 后者显式写 `tone:'sp'`。英文短码 `hp|mp|sp|xp|exp|ep` 走**整词匹配**
> （否则 `temperature` 会被染成 mp），长词 `health`/`mana`/`stamina` 才做子串匹配。

### 3.3 自定义控件

```js
SBK.ui.hud.type('星级', function (f) {
  return { t: 'div', c: 'sbk-row', k: [
    { t: 'span', c: 'sbk-label', x: f.label },
    { t: 'span', c: 'sbk-val', x: '★'.repeat(f.value) }
  ]};
});
```

返回的是 vnode：`{ t: 标签, c: class, s: style, x: 文本, k: 子节点, on: 点击函数, oc: 内联 onclick 字符串 }`。**一份结构两条出口**——`hydrate()` 走 DOM（`on` 生效），`snapshot()` 走字符串（`oc` 生效）。要在两条出口都能点的控件必须**同时给 `on` 与 `oc`**（函数没法塞进字符串）。`SBK.ui.hud.types()` 看已注册的类型。

> `SBK.ui.hud` 作为**渲染器已废弃**（直接调它会告警并返回惰性句柄，不写 DOM），但
> **`.type()` / `.types()` 仍是公开的注册入口**，注册进去的控件在状态面板里照常生效。
> 废弃原因见 `../README.md` 的「`SBK.ui.hud` 已废弃」节。

## 四、`SBK.parse` 接口

```js
SBK.parse(text)  // -> { state, order, cleanedText, skipped } | null
```

- 无状态块返回 **`null`**；空块（`[状态][/状态]`）返回**对象**，`state` 为空——这两者要分清。
- `state[键] = { type, value, max?, unit?, raw }`，`raw` 是归一化后的原始值字符串。
- `order`：键的输出顺序。
- `cleanedText`：**移除状态块后的原文**（连带压掉多余空行、去首尾空白）。用它把状态块从正文里藏掉。
- `skipped`：跳过的坏行数组，调试用。

配套方法：`SBK.parse.pattern(cap)` 取推荐匹配式、`SBK.parse.config({block})` 改块名、`SBK.parse.value(raw)` 单值分类器（写自定义控件时复用）、`SBK.parse.wrap(body)` 给裸块体补回方括号标记。

### 4.1 消息事件载荷形状（实机确证）

自己调 `feed()` 或写自定义事件处理时要知道正文从哪来。探针实测 `message:new` / `message:mount` / `message:done` 三者载荷**形状完全一致**，恰 4 个键：

| 键 | 类型 | 说明 |
|---|---|---|
| `content` | string | **正文就是这个字段。** 不用试探 `text`/`body` 之类的别名 |
| `id` | string | **字符串，不是数字。** 开场白是 `"greeting"` |
| `role` | string | `'ai'` 或 `'user'`。基座只吃 `'ai'` |
| `serverId` | object | `null` 表示服务端还不认得这条消息 → **该条不可 `sdk.message.edit`**，写回前必须判空 |

`ready` 的载荷是 `undefined`，纯时序信号，**取不到正文**。

```js
SBK.on('done', function (payload, bubbleRoot) {
  if (payload.role !== 'ai') return;
  var r = SBK.parse(payload.content);
});
```

`bubbleRoot` 是**基座桥接层合成的第二参**，不是 SDK 给的（SDK 回调只有 1 个实参）。它只在回调内同步有效，见坑 5。

基座可订阅的事件（`SBK.on(名, fn)`）：`mount` `done` `stream` `theme` `switch` `ready` `dispose`，加上状态仓自己派发的 `state`。

### 4.2 存档：`SBK.store`

**没有自动存档。** 存档必须显式调用：

```js
SBK.store.save();                       // 缺参 = 以当前 state 作业务整文档
SBK.store.save({ 章节: 3, 好感: {…} });  // 业务整文档替换；未显式给出的 _sbk* 内部键会保留
SBK.store.merge({ 设置: {…} });           // 顶层补丁合并，不覆盖其它业务字段
var doc = SBK.store.load();             // 同步；没有存档 / 读不到一律返回 null，绝不抛
SBK.store.clear();                      // 删档
SBK.store.key('my-save');               // 换存档键（1..64 字符，禁 `:`）
```

- `save()` 与 `merge()` 共用**800ms 尾部合并队列**，同一窗口只落一次盘。`save()` 是业务整文档语义；`merge()` 只叠顶层补丁。
- 业务 `save()` 会保留旧文档中调用方未显式覆盖的 `_sbk*` 内部键，避免一次业务保存抹掉主题偏好。
- `load()` **同步且永不抛**。瘦预览下平台 `save.get` 同步抛错时，基座转入 cache/内存；不会把“未知远端”误当空文档回写。
- 降级链 `sdk.save` → `sdk.cache` → 内存，对调用方透明。平台 `save.set` 上限是 20 次/60s；SBK 为业务方留余量，本地按 18 次/60s 节流，超出会告警并保留到 cache。`save.remove` 不走该本地写入桶。
- `_sbk` 前缀是**基座保留字段**（主题偏好存在 `_sbkTheme`），别自己写这个前缀的键，也不会渲染进面板。

**业务作用域由你自己定义。** 基座不替你决定「存哪些字段、什么时候存、切会话算不算同一份存档」——
这正是 `schema.persist` 被删掉的原因：它没有定义过这三件事中的任何一件，所以不可能有正确的实现。
典型接法是自己订阅：

```js
SBK.on('done', function () { SBK.store.save(); });        // 每轮存
var d = SBK.store.load(); if (d) SBK.state.replace(d);    // 开局读档
```

> 🚨 **切会话（`switch`）时基座会清掉公开状态**，只保留 `_sbk*` 内部字段（否则上一个会话的数据会串到下一个）。
> 如果你的存档是**按会话分开**的，就在 `switch` 里自己 `load()` 对应那一份再 `state.replace()`；
> 基座不做这件事，因为它拿不到「哪份存档属于哪个会话」这个映射——`switch` 事件的载荷形状尚未确证，
> 基座**不假定它带会话 id**。

## 五、常见坑

1. **指望正则刷新功能栏上的东西。** 功能栏静态（§5.6）：`h_()` 只在装载时跑一次，正则输入还是 `statusbar` 字段**自身**而不是消息内容。所以功能栏字段只能放一个宿主容器占位标记，`chrome` 的入口按钮与 `pinned` 精简条**都是 JS 在事件回调里挂 DOM**、靠订阅 `state`/`done` 更新。想要跟着对话变的状态数据，用 `status`（气泡内面板）。
2. **在脚本顶层渲染。** 作者脚本早于 DOM 执行（硬约束 17，实测顶层取节点返回 `null`）。所有 DOM 写入放进事件回调。
3. **挂 `ready` 做首屏。** `ready` **无补发且最后到**（§4.1 实测）。挂 `mount`/`done`。
4. **用反引号包状态块。** 🚨 §5.4：``` ``` ``` 与 `` ` `` 里的内容被抽成占位符保护，**HTML 会原样成文本**。写进 persona 的示例、或让模型用行内代码包状态块，都会让整块变成一坨可见的原始文字。**别用反引号。**
5. **自己 `document.querySelector` 查气泡内元素。** §4.3：平台改写了 `Document.prototype.*`，靠模块级游标 `gc` 过滤，`gc===null` 时气泡内元素**全部查不到**，且跨 `await`/`setTimeout` 即失效。用回调第 2 参 `bubbleRoot` + `SBK.dom.inBubble`。（平台级节点如 `[data-chat="root"]` 在回调内**是**可达的，这点实测修正过。）
6. **匹配式写成能匹配空串。** §5.2：`empty-match` 让**整条规则被撤销**，作者只看到「规则没生效」。
7. **匹配式写成语法错的 `/…/`。** bad-regex 会让整条规则静默丢弃。裸字面量实机生效（卡 64304 A/B 2026-08-30），但建议统一 `/…/`（约定，生成器出 WARN 不阻断）。
8. **快照产物太肥。** §5.2 预算 `max(262144, 输入长度×4)`，超限整条回滚。基座产物约 900 字符/块，够紧凑；自己拼就注意别加缩进换行。
9. **写死颜色。** 一律 `var(--chat-*)`，否则平台深浅色切换后瞎掉。（§9 实测深色 `--chat-accent:#ff6d97`，仅作视觉参考。）
10. **SVG 里挂 `onclick`。** 实测 `<circle onclick>` **被删**。交互挂 HTML 壳。HTML 元素上**任意 `on*` 都可用**（`onclick`/`onmouseenter` 实测均保留）。
11. **inline `on*` 里写 `a[0]>1`。** `]>` 命中 `SAFE_FOR_XML`，**整条属性被删**。比较运算符两侧留空格，或直接用 `SBK.dom.h` 的函数式 handler 走 `addEventListener`。
12. **自写 `data-*`。** 实测 `data_mine=null`，全删。用 class。

## 六、给模型的输出约定（粘进 `personality`）

以下整段可直接粘贴。**不要用反引号包它**（见坑 4）。

```text
【状态输出格式】
每一轮回复的最末尾，都必须附上一个状态块，格式如下：

[状态]
体力: 当前值/上限
灵力: 当前值/上限
境界: 境界名|当前经验/升级所需
银钱: 整数
装备: 槽位:名|槽位:名:说明
属性: 攻:数 防:数:说明 敏:数
位置: 大区-中区-小地点
好感: 角色名=数值, 角色名=数值
标记: 词, 词
[/状态]

规则：
1. 每一轮都要输出，一轮一个，不能省略、不能合并到下一轮。
2. 放在正文最后，状态块之后不要再写任何内容。
3. 用方括号标记 [状态] 与 [/状态]，不要用尖括号，不要用反引号包裹。
4. 一行一个字段，格式是「字段名: 值」，冒号后面留一个空格。
5. 数值型字段只写数字，不要加「点」「滴」这类量词，不要写「约」「大概」。
6. 有上限的量写成 当前/上限（例：体力: 84/100），上限不变就一直照抄。
7. 等级类字段写成 名称|当前/上限，中间用竖线（例：境界: 炼气三层|120/300）。
8. 属性类字段写成 键:值，用空格或逗号分隔（例：属性: 攻:12 防:8 敏:15）；
   要补充成因就再加一个冒号写第三段（例：防:8:破甲）。
9. 装备类字段写成 槽位:名，项与项之间用竖线（例：装备: 头:斗笠|身:麻衣）；
   同样可加第三段写说明（例：身:麻衣:防御+2）。
10. 地点类字段写成 大区-中区-小地点，用连字符分段（例：位置: 内城-东市-药铺）。
11. 多角色数值写成 名字=数字，用逗号分隔（例：好感: 苏九=61, 阿澈=25）。
12. 标签类字段用逗号分隔的词（例：标记: 中毒, 疲劳）；没有任何标记时写「标记: 无」。
13. 字段名与顺序保持固定，数值随剧情变化，没变化就照抄上一轮的值。
14. 状态块内不要写解释、不要写括号注释、不要用 markdown 列表符号。
```

这段覆盖了**协议能自动推断的那九种**数据类型，做卡时按自己的字段裁剪：只用得上进度条和标签就删掉 7–10 条。**竖线（`|`）、连字符（`-`）、冒号（`:`）、等号（`=`）四个分隔符各有分工**，混用会让类型判定落到 `text`，具体优先级见 §1.2。

`time` / `summary` / `turn` 不在这段约定里，因为它们**不靠推断**（见 §3.2）：模型照常写普通文本行（`时间: 第三日 黄昏`），
你在 `fields` 里写上 `type` 就会按对应形态渲染。要用的话在上面加一行字段名即可，不需要教模型任何新格式。

做卡时把字段替换成自己那套，`fields` 与这段文本**保持一致**。

> **第 3 条（方括号、不用反引号）是这段文本里最不能动的一条**，原因在 §1.1：
> worker 的剥壳正则会把 `<状态>` 当非白名单中文标签**整个删掉**，反引号里的 HTML 则会
> 原样成文本（§5.4）。有人「顺手改回尖括号」，状态栏就会在某些路径上变成一坨原始文字。

字段命名建议：

- 名字短，2–4 个字。功能栏窄（实测预览视口宽 `323px`），名字长了换行。
- 不要在字段名里用冒号（会被当分隔符）。
- 有上限的量一律写 `当前/上限`，别只给当前值——不然进度条不知道画多满（真要只给当前值，就在 schema 里补 `max`）。

最后一条：**开了 `chrome` 或 `pinned` 就不能让卡片的 `statusbar` 字段留空**，且必须含宿主标记（默认 `{{hud}}`）。字段为空时平台不渲染 statusbar 槽位，宿主会退化到 `[data-slot="left"]` 浮层。该字段上限 200 字符。（只开 `status` 的话状态面板在气泡内，不依赖这个字段。）
