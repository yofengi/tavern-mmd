# 当前 MMD 同层卡：独立页面制作

适用：用户要同层卡、独立游戏页面、全屏 HUD，或接管输入、主叙事和整页导航。**目标仍为 `/mmd`（chatVersion:0/缺省），不是第四个平台。** iframe 的 sandbox 属性不等于 `/mmdsandbox`。新聊天页先读 `../platforms/mmd-sandbox.md`，不套用本基座。

## 1. 先确定玩法与数据来源

在项目 main.md 记录以下选择；用户已经表达的内容直接沿用，不重复询问：

| 项目字段 | 可选方向 |
|---|---|
| 目标平台 | 当前MMD |
| 制作类型 | 同层卡 / 独立页面 |
| 平台连接 | 原生桥接（默认）；后端直连仅在有已验证适配器时选用 |
| 状态权威 | AI 叙事驱动 / 程序规则驱动 / 明确字段分工的混合 |
| 存档来源 | 消息重建 / 有可靠作用域的独立存储 |
| 验证层级 | 静态、本地浏览器、真实 MMD、真机，分别记录 |

仅要气泡状态栏或悬浮面板时，继续使用雷达法/影渲法。不要因为出现“游戏”“背包”两个词就自动替换整页。

### 两种作品都支持

- **互动聊天 UI**：自定义对话、选项、地图与人物面板；平台的消息、模型、历史、设置以 MMD 为准。AI 产生的状态字段从消息解析，规则写入世界书。
- **小游戏**：引擎负责资源、回合、事件和判定，先结算并确认保存，再更新 UI；AI 可描写已结算事实。程序控制的字段不再由模型生成第二份真值。

连接方式与玩法权威是独立选择：原生桥接也能服务程序规则游戏，不要求先写后端直连。若需要 AI 提出规则变化，将它当待校验提案，由引擎接受或拒绝，不从按钮文案和 DOM class 反推规则。

## 2. 默认架构

```text
独立网页 UI（Frame）
  ↔ 一次握手后的 MessagePort
  ↔ Host（原生桥接、可选引擎与受限存档）
  ↔ MMD 原生页面继续执行发送、模型与历史
```

这是贪心鬼仓库默认路线的架构思路：独立显示，原生前端在后台执行。**不能删除原生 DOM，也不能承诺桥接已覆盖全部原生功能。** 尚未镜像的功能通过“返回 MMD”入口使用。

- Frame 不读取 parent.document，不接收 Cookie/Token 或任意父页请求能力。
- Host 暴露明确动作，操作前检查当前 capability，操作时重验目标。
- DOM 快照只代表已观察到的页面内容，不是完整服务器历史；DOM 消息 ID 不作为永久存档主键。
- “已触发发送”“回复已结束”“服务器已保存”分开表示。原生发送动作成功不能替代后两项。
- 所有公共初始化是文档级单例；逐消息不要重复创建 Host、iframe、监听器或存储服务。

接口与存档合同见 [运行时说明](../runtime/mmd-native-bridge.md)。后端方向见 [后端适配边界](../runtime/mmd-backend-host.md)。

## 3. 用基座从零制作

现成资产：[same-layer-kit](../../assets/same-layer-kit/README.md)。代码为独立实现，现已内置对应固定上游 61 项动作的处理器，没有复制上游源码。

1. 将整个 `assets/same-layer-kit/` 复制到项目 `工作/同层卡/` 作为源码，记录在 main.md。先读 `../beautify/style-system.md`，沿用用户选定风格；基座外观只是功能演示，不是所有作品的默认美术风格。
2. 先读 [对话页模块制作](same-layer-dialogue.md)，用 `frame-ui-config.js` 选择模块，再修改 `frame.html` / `frame.css` 与各视图文件。可换成自己的组件框架，但发布时输出自包含页面；不要把开发服务器 URL 交付给玩家。
3. 聊天型作品可用构建器 `--no-engine`。规则游戏修改 `core.js` 的引擎、公开投影、状态校验和迁移；不要仅改显示字段而遗忘存档格式。
4. 按 [统一预览与审核](same-layer-review.md) 建立作品配置，以旧 MMD 联动页验证操作、退出返回、会话切换与窄屏。游戏还需保存/读档专项检查。原生页与同层页共用模拟状态，正式桥接保持原样；本地结果不能作为真实平台证据。
5. 接入原生桥接。基座内置 DOM 消息读取/发送与模型列表、筛选、切换和设置，可随卡自动启动；已有贪心鬼 NativeBridge 实例也有模型适配。模型 UI 默认启用，可用 --no-models 关闭。先读 [模型制作模块](../runtime/mmd-model-controls.md) 与 [原生能力清单](../runtime/mmd-native-capabilities.md)；其他 52 项已实现动作也已内置，调用合同见 [原生动作模块](../runtime/mmd-action-modules.md)，按需设计 UI。上游仅定义的 6 项仍未实现。
6. 游戏存档要求可靠的账号/角色/会话解析器。接口缺失或不确定时停用持久游戏，保留聊天与返回原生入口；不要用固定 main、角色名字、DOM 序号或扫描 localStorage 猜作用域。
7. 用已有 creation 文档写人设、开场与世界书。世界书源仍走 worldbook_tool.py；长期规则与 AI 输出约定放世界书，动态进度由选定事实源维护。
8. 用统一入口生成四字段 JSON 与 manifest，运行标准校验、专项反向校验和浏览器检查，并阅读统一报告。需要整卡时按 `../output/card-json.md` 封装为 v2 PNG；游戏源代码不作为 AI 每轮输出要求。

### 构建、预览与审核

复制资产中的作品配置并填写源码位置，从实际 skill 根目录运行：

```sh
python scripts/review_same_layer.py --project <作品配置.json> --out <新的审核目录> --browser required
```

打开输出中的 `review-report.html`，从报告进入 MMD / 同层卡联动预览。须用本地 HTTP 服务提供整个审核目录；依赖、配置和证据说明见 [统一指南](same-layer-review.md)。生成的发布包在 `release/`，同层 Frame 单独打开不能验证宿主。

需要单独排查构建时仍可调用 `build_same_layer.py`、`validate.py`、`verify_same_layer.py`。构建器的 `--preview` 只生成简化 Mock，不替代作品的联动验收。

## 4. 写卡时容易混淆的边界

- `<script>` 不适合作为逐消息自定位引擎，仍不妨碍文档级初始化独立 Frame。Frame 里的组件不需要反复使用 img onerror。
- 原始消息标签白名单与已创建 iframe 的 DOM 能力分开；不要将一层的限制直接推广到另一层。
- 元素 ID 使用时间戳/实例前缀避免碰撞；导入 JSON 的规则 `id` 固定 `-1`。
- Frame 自有点击事件不传播到父文档；宿主控件避免误触原生页面。模拟原生 input/click 时保留平台需要的冒泡，不对所有事件一律 stopPropagation。
- 官方跨设备 sdk.save 属于新页；本基座的宿主 localStorage 是本地存档，换设备需要导出导入。
- 普通聊天型 UI 不必套用复杂事务/战斗引擎。确有长期进度的作品才要求相应存档验收。
- AI 驱动状态栏需要蓝灯输出协议；程序引擎维护的状态不强制模型每轮吐 `<status>`。两者在同一作品中共存时按字段分工。

## 5. 验证与交付

同层卡按 `../quality/checklist.md` 的同层专节检查，不套用 onerror 的属性引号与逐气泡结构清单。最少覆盖：

- 唯一实例、重复点火、退出/返回、路由离开与回到原卡；
- 输入草稿不被覆盖、发送不自动重试、断线有可用的原生入口；
- 保存失败、坏档、错会话、读档后的旧回调、跨版本迁移；
- 分片缺失/乱序/损坏、实际 String.replace 语义、整个载荷还原与脚本语法；
- 桌面与窄屏本地浏览器；真实 MMD 和实体手机另列证据，不用本地 PASS 代替。

当前资产能做本地演示和开发起点；真实旧 MMD 适配、CSP、路由与真机应在项目部署时验证。不自动发模型请求、导入卡片或公开发布。
