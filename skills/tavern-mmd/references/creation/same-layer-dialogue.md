# 同层卡对话页与可组合模块

仅用于当前 MMD 旧聊天页（`chatVersion:0` / 缺省）。先读 [同层卡制作](same-layer-card.md) 和 [动作合同](../runtime/mmd-action-modules.md)。

## 页面结构

基座参考用户提供的贪心鬼测试卡及固定上游 `ae96d63` 的对话页分区，独立编写 HTML/CSS/JS，没有复制上游 Vue、GSAP 或第三方图片。采用顶部角色与功能菜单、中央编号消息、底部模型与输入区、独立功能弹窗；小游戏在桌面右侧、窄屏下方。深浅两套配色只属于示例，创作时按角色题材重做视觉。

| 模块开关 | 默认界面与操作 |
|---|---|
| messageActions | 复制、编辑、同步草稿、文本变换、保存、重新生成、删除、回溯、从消息开启故事 |
| models | 模型列表、分类、切换、模型设置；沿用 [模型模块](../runtime/mmd-model-controls.md) |
| conversations | 打开/关闭、切换、新建、备注、确认删除非当前会话 |
| persona | 模式、名字、性别、身份，同步单字段和提交 |
| supplement | 内容草稿、位置选择/确认/取消、提交 |
| instructions | 列出指令，保护已有草稿，填入输入框后由玩家发送 |
| settings | 读取、提交、关闭；逐项修改入口返回 MMD |
| sharing | 读取分享信息、派发生成/复制链接、关闭 |
| navigation | 刷新、收藏、评论、退出；始终保留返回 MMD |
| more | 原生更多菜单，跳转已有模块；背景、自定义指令、教程返回原生页面 |
| game | 规则引擎示例、公开数值、行动、AI 叙述、进度导入/导出 |

61 项已实现动作均有页面入口或属于模块操作流程，**不意味着 61 个独立按钮，也不意味着全部原生页面已重写**。背景/自定义指令没有编辑接口；对话设置没有逐项写入接口。模型设置有独立的写入动作。六项仅定义动作仍不添加假按钮。

## 作者如何组合

1. 复制完整 `assets/same-layer-kit/`，保持 Host 与 Frame 文件同一版本。
2. 在 `frame-ui-config.js` 中选择 `theme: 'dark'` 或 `'light'`，把不需要的 `modules` 项改为 `false`。这是界面开关，不改变 Host 权限；要限制调用范围，使用 Host 的 `allowedActions`。
3. `frame.html` 管结构/文案；`frame.css` 管 `--sl-*` 主题与窄屏；`frame-features.js` 管消息和通用弹窗；`frame-panels.js` 管各功能表单；`frame-models.js` 管模型。`frame.js` 继续负责通信、发送和游戏流程。不要在界面读取父页 DOM。
4. 游戏逻辑继续修改 `core.js`，纯聊天卡用 `--no-engine`；不用模型层用 `--no-models`。UI 隐藏与功能不打包是两个概念：这些开关控制启动/显示，不做源码裁剪。
5. 构建器按固定顺序内联 Frame 模块和 CSS，交付仍是自包含四字段正则 JSON。整卡另封装 v2 PNG。

新增一个面板时，先确认对应动作已经实现，列出读取组、打开/关闭动作与写入参数，再复用 `MmdSameLayerPanels` 的模式。给 `definitions` 增加声明、`render` 增加视图，并在配置声明开关。自定义无原生动作的地图/背包组件读取游戏公开状态，不能把 DOM 文案当规则真值。

## 必须保留的交互约束

- 每个按钮依最新 capability 与目标限制启用，未知入口留禁用原因；更多菜单不会放行重置等未审核的通用项。
- 表单保留本地输入。原生内容外部变化时提示过期并停用写入；重新读取前确认是否丢弃草稿。自己成功执行的动作读取新版本后保留其他未提交字段。
- 删除与回溯先展示目标并征得玩家确认，再在同一次操作中请求/使用绑定令牌。取消本地确认不打开原生删除框，旧目标/旧版本会被拒绝，不自动重试。
- 指令填入与同步输入都保护不同的原生草稿。发送只接受空原生输入或与将发送内容完全相同的草稿，点击前再验输入、控件及消息根节点。
- 返回/关闭会处理对应原生面板；补充位置选择器先取消。已同步字段不宣称能够撤销。会话切换会重建 Frame，清除旧草稿与确认，重新读取游戏作用域。
- 消息、链接、人设、提示均以文本节点呈现，不插入原生 HTML。更新消息时保留节点与滚动位置，表单不被定时快照覆盖。
- 分享复制/发送/提交结果不等于系统剪贴板成功、完整模型回复或服务端持久化成功。

## 预览与审核

作品默认用 [统一预览与审核](same-layer-review.md)：`review_same_layer.py` 一次生成发布文件、旧 MMD / 同层卡联动预览、静态与浏览器检查、统一报告。两页共享本地状态；发布桥接与 Frame 保持原样。复制资产中的 `same-layer.project.example.json` 后配置作品信息。

`build_same_layer.py --preview` 的 Mock 和 `preview_same_layer_dialogue.py` 的独立 DOM 夹具保留作组件诊断，不代表真实 MMD。基座 UI 回归用 `test_same_layer_dialogue_browser.mjs`；统一入口的作品检查用 `review_same_layer_browser.mjs`。完整命令、环境依赖与精度边界见统一指南。

本地通过只证明所列模拟合同与页面行为；真实 MMD 导入、官方前端变化、账号/角色/会话解析与实体手机仍由作品单独验收。
