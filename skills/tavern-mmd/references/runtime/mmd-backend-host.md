# 同层卡后端适配：进阶路线边界

适用：用户明确要求摆脱原生 DOM，或已有经过当前 MMD 验证的宿主后端适配器。普通同层卡与小游戏优先使用 [原生桥接](mmd-native-bridge.md)。

**当前基座未实现 MMD 私有后端直连。** 黑洞猫教程的 MmdAdapter 需要外部 semanticTransport，默认 Mock；历史端点清单不等于当前平台合同。不要把旧路径和猜出的参数写成可用接口。

可复用的部分是独立 Frame、受限消息通道、规则引擎和存档思路。原生桥接的 accepted 与后端生成的流结束/持久化语义不同，不能只把 sendMessage 改名为 generate。

在具体项目有接口证据之后，按所需能力逐项实现：

1. 当前账号隔离、角色与会话作用域；模型与设置实时读取。
2. 一次生成的请求身份、业务返回、流式内容与结束标记。
3. 消息编号、历史回读、unknown 状态与人工可执行的对账方式。
4. 会话切换后重新绑定；旧任务不得写入新作用域。
5. 明确原生界面与独立界面如何同步，退出后怎样继续原生聊天。

游戏页面只接收必要的语义能力。登录态留在宿主，不能向 Frame 提供任意 URL 代理、凭据或全部存储。没有验证服务器取消语义时，前端停止等待不能记为已取消。

先用 Mock 验证协议和故障，再按用户已授权的真实操作范围做单次闭环。分别记录静态、本地浏览器、真实 MMD 与真机结果，不因本地测试通过而宣称直连可用。
